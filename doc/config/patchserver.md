# patchserver options

See doc/config/README.md for the file format, layers, environment variable names, and reload triggers, and doc/config/logging.md for the full logging grammar.

The Applies column says when a changed value takes effect after a configuration reload or a live edit. No option in this file needs a restart, so the panel's config page marks none restart-required. The socket layer applies the network options through `SocketMgr::ApplySettings`; the reload triggers that call it arrive in milestone 4.15.

| Option | Type | Default | Environment variable | Applies | Meaning |
|---|---|---|---|---|---|
| `LogsDir` | string | `logs` | `AMBROSE_LOGS_DIR` | Live | Folder for log files, relative to the working directory unless absolute; created when a File appender exists |
| `BindIP` | string | `0.0.0.0` | `AMBROSE_BIND_IP` | Rebinds live like the port option | Local address the listener binds; 0.0.0.0 listens on every IPv4 address |
| `PatchServerPort` | uint16 | `12500` | `AMBROSE_PATCH_SERVER_PORT` | Rebinds live; the new listener opens before the old one closes, and a failed bind keeps the old one | TCP port the patch server listens on for clients |
| `Network.Threads` | uint32 | `1` | `AMBROSE_NETWORK_THREADS` | Live; new threads start at once, and removed threads stop taking sockets and exit when their last connection closes | Network threads that read and write sockets (1-256) |
| `Network.MaxFrameSize` | uint64 | `4194304` | `AMBROSE_NETWORK_MAX_FRAME_SIZE` | Next connection | Largest frame in bytes a client may send, checked before the frame is buffered (17 to 1 GiB) |
| `Network.MaxDmlMessages` | uint32 | `1024` | `AMBROSE_NETWORK_MAX_DML_MESSAGES` | Next connection | Most DML messages one frame may chain (at least 1) |
| `Network.MaxSendQueueBytes` | uint64 | `16777216` | `AMBROSE_NETWORK_MAX_SEND_QUEUE_BYTES` | Next connection | Most bytes a connection may have waiting to be sent (1 MiB to 1 GiB). A frame that would pass the limit is not queued and the connection is closed, so a client that stops reading cannot grow server memory without bound |
| `Network.LongFrameLength` | string | `BodyOnly` | `AMBROSE_NETWORK_LONG_FRAME_LENGTH` | Next connection | What a long frame's 32-bit length counts: `BodyOnly` or `HeaderAndBody`, until doc/CAPTURE.md settles it |
| `Network.OutKBuff` | int32 | `-1` | `AMBROSE_NETWORK_OUT_K_BUFF` | Next connection | Socket send buffer in bytes; -1 keeps the operating system default |
| `Network.TcpNoDelay` | bool | `1` | `AMBROSE_NETWORK_TCP_NO_DELAY` | Next connection | Disable Nagle's algorithm so small frames go out at once |
| `Admin.Enable` | bool | `0` | `AMBROSE_ADMIN_ENABLE` | At startup, and live once 4.15's reload triggers call `ServerApp::ReloadAdminApi`: 1 opens the listener and 0 closes it without a restart | Serve the admin API, an HTTP/1.1 and WebSocket listener that answers `GET /api/health`, `GET /api/status`, `GET /api/apps`, `GET /api/capabilities` and `GET /api/settings`, stops the server with `POST /api/shutdown`, streams the log over the `/api/logs` WebSocket today and carries every later operations endpoint. Off by default, so nothing listens until an operator turns it on |
| `Admin.BindIP` | string | `127.0.0.1` | `AMBROSE_ADMIN_BIND_IP` | At startup, and live on a reload: a safe change rebinds, and a bind that fails keeps the old listener serving | Address the admin API binds. Only a loopback address is served without TLS: any other address, `0.0.0.0` included, stops startup with an error naming `Admin.AllowPlainHttpRemote` unless that option is 1, and on a reload is refused with the old binding still serving. On Windows the listening socket carries `SO_REUSEADDR`, so another process running under any account on the same machine can bind the same address and port and take the connections meant for it; the phase 17 review notes track closing that |
| `Admin.Port` | uint16 | `12510` | `AMBROSE_ADMIN_PORT` | Like `Admin.BindIP` | TCP port the admin API listens on; 0 takes a free port the operating system picks |
| `Admin.Token` | string | empty | `AMBROSE_ADMIN_TOKEN` | At startup, and live on a reload, where the old token stops answering at once and no connection is dropped | The bearer token every admin API request carries as `Authorization: Bearer <token>`, at least 16 printable characters with no spaces. Empty uses `Admin.TokenFile`. Prefer the environment variable or the file, so the token stays out of config files |
| `Admin.TokenFile` | string | empty | `AMBROSE_ADMIN_TOKEN_FILE` | Like `Admin.Token` | File holding the token while `Admin.Token` is empty. An existing file is read, and otherwise a new 64-character token is written to it with permissions that let only the account running the server read it. Empty uses `admin/<app>.token` in the Ambrose data folder (`%LOCALAPPDATA%/ProjectAmbrose` on Windows, otherwise `$XDG_DATA_HOME/project-ambrose` or `~/.local/share/project-ambrose`), and where the environment names no such folder at all the same path beside the config file, so an account with no home directory still starts. A file that holds no usable token stops startup instead of being replaced |
| `Admin.AllowPlainHttpRemote` | bool | `0` | `AMBROSE_ADMIN_ALLOW_PLAIN_HTTP_REMOTE` | Like `Admin.BindIP` | Opt in to serving the admin API as plain HTTP beyond this machine. The token is still required, but it, every command and every log line cross the network unencrypted, so anyone on the path can read them and reuse the token. Startup logs a warning naming this option whenever it is what allows the binding |
| `Admin.CertificateFile` | string | empty | `AMBROSE_ADMIN_CERTIFICATE_FILE` | Like `Admin.BindIP` | Certificate chain in PEM that the admin API serves over TLS, together with `Admin.PrivateKeyFile`. It runs leaf first, each certificate followed by the one that issued it. Both files are read when the listener opens and again on every reload, and refused by name when the key does not belong to the leaf, the chain is out of order or the dates do not hold today, so the listener never opens on a certificate it cannot serve. A reload swaps the pair for the next handshake without dropping open connections, and keeps the old pair serving when the new one will not load. The fingerprint and expiry are logged when it opens and whenever it changes, with a warning from thirty days before it expires. With both set, a bind beyond this machine needs no plain-HTTP opt-in |
| `Admin.PrivateKeyFile` | string | empty | `AMBROSE_ADMIN_PRIVATE_KEY_FILE` | Like `Admin.BindIP` | Private key of `Admin.CertificateFile`; either one set without the other stops startup |
| `Admin.AuthFailureBurst` | uint32 | `10` | `AMBROSE_ADMIN_AUTH_FAILURE_BURST` | Live on a reload; changing either limit gives every address a fresh budget | Failed authentications one client address may spend in a burst (1-100000). Past the burst that address is answered 429. The token is compared before the budget is read, so the right one always answers however empty the budget is, and a request the listener cannot read a client address from is answered 401 without spending anyone's budget |
| `Admin.AuthFailuresPerSecond` | float | `1` | `AMBROSE_ADMIN_AUTH_FAILURES_PER_SECOND` | Like `Admin.AuthFailureBurst` | How fast that budget refills (0-100000); 0 never refills, so an address that spent its burst is answered 429 for every wrong token until the limits change or the server restarts, while the right token still answers |
| `Admin.MaxRequestBytes` | uint32 | `262144` | `AMBROSE_ADMIN_MAX_REQUEST_BYTES` | At startup, and live on a reload, which rebinds the listener | Largest request body the admin API takes and largest WebSocket message it reads (1024-16777216). A larger body is answered 413 once the token has been checked, and a larger frame closes the socket. The HTTP layer buffers a body in memory before any check runs, so this bounds what a handler sees, not what an unauthenticated peer can make the process allocate; the phase 17 review notes track that |
| `Admin.Threads` | uint32 | `2` | `AMBROSE_ADMIN_THREADS` | At startup, and live on a reload, which rebinds the listener | Threads the admin API serves requests on (2-64) |
| `Admin.DashboardDir` | string | empty | `AMBROSE_ADMIN_DASHBOARD_DIR` | Live | Folder holding the built panel, which the admin API serves at `/` without a token; empty means the `dashboard` folder beside the executable. Only GET and HEAD, only the file types the build writes and only files inside the folder are served, and `/` names this option when the folder holds no panel |
| `Admin.AllowedHosts` | string | empty | `AMBROSE_ADMIN_ALLOWED_HOSTS` | Live | Comma-separated host names the admin API answers for beside IP addresses and `localhost`. A request naming any other host is refused with 400, so a web page elsewhere cannot point a name of its own at this listener and reach it through a visitor's browser |
| `Admin.SessionIdleMinutes` | uint32 | `720` | `AMBROSE_ADMIN_SESSION_IDLE_MINUTES` | Live, for sessions already open too | Minutes a browser session that signed in to the panel with the token may go unused before it ends (5-10080) |
| `Admin.SessionLifetimeHours` | uint32 | `168` | `AMBROSE_ADMIN_SESSION_LIFETIME_HOURS` | Live, for sessions already open too | Hours a browser session lasts at most however often it is used (1-720). Rotating the token ends every session at once |
| `Log.Async.Enable` | bool | `0` | `AMBROSE_LOG_ASYNC_ENABLE` | Live | Write log lines on a dedicated thread; shutdown and exit drain every queued line |
| `Log.Async.QueueSize` | uint32 | `65536` | `AMBROSE_LOG_ASYNC_QUEUE_SIZE` | Live | Queued lines before the full-queue policy applies (1024-16777216) |
| `Log.Async.QueueFull` | uint8 | `0` | `AMBROSE_LOG_ASYNC_QUEUE_FULL` | Live | 0 waits for room, 1 drops the line and logs the drop count |
| `Log.Utc` | bool | `0` | `AMBROSE_LOG_UTC` | Live | Timestamps and file names in UTC instead of local time |
| `Log.PendingBuffer` | uint32 | `1000` | `AMBROSE_LOG_PENDING_BUFFER` | Live | Lines kept for an appender whose type registers later, such as DB |
| `Console.Colors` | uint8 | `1` | `AMBROSE_CONSOLE_COLORS` | Live, from the next line written | 0 never, 1 when stdout is a terminal, 2 always; `NO_COLOR` disables 1 |
| `Console.Enable` | bool | `1` | `AMBROSE_CONSOLE_ENABLE` | At startup, and live once 4.15's reload triggers restart the console reader | Read commands such as `help`, `status` and `shutdown` from standard input; 0 starts no input thread. On a terminal the app draws an `Ambrose> ` prompt with line editing, history and tab completion of command names; a redirected input is read line by line instead. A closed or redirected-from-nothing input leaves the server running, and a terminal owned by another foreground job is not read |
| `Appender.Console` | appender | `1,3,7,"1 9 3 13 7 7"` | `AMBROSE_APPENDER_CONSOLE` | Live | Colored console output at Info with time, level and category |
| `Appender.Server` | appender | `2,2,7,Patch.log,w` | `AMBROSE_APPENDER_SERVER` | Live | Patch.log in LogsDir, rewritten each start, with time, level and category |
| `Appender.Errors` | appender | `2,4,7,PatchErrors.log,a,16M,10` | `AMBROSE_APPENDER_ERRORS` | Live | Warnings and worse, appended across restarts, rotated at 16 MiB keeping 10 backups |
| `Appender.Stream` | appender | `3,2,0,1000` | `AMBROSE_APPENDER_STREAM` | Live | Live records for the admin API with a 1000-record backlog |
| `Logger.root` | logger | `3,Console Server Errors Stream` | `AMBROSE_LOGGER_ROOT` | Live | Required fallback for every category |
| `Logger.server` | logger | `3,Console Server Errors Stream` | `AMBROSE_LOGGER_SERVER` | Live | App lifecycle, config and logging messages |
| `Logger.sql` | logger | `4,Console Server Errors Stream` | `AMBROSE_LOGGER_SQL` | Live | Database messages, warnings and worse |
| `Logger.network` | logger | `3,Console Server Errors Stream` | `AMBROSE_LOGGER_NETWORK` | Live | Sockets and message traffic |
