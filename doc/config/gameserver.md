# gameserver options

See doc/config/README.md for the file format, layers, environment variable names, and reload triggers, and doc/config/logging.md for the full logging grammar.

The Applies column says when a changed value takes effect after a configuration reload or a live edit. No option in this file needs a restart. The socket layer applies the network options through `SocketMgr::ApplySettings`; the reload triggers that call it arrive in milestone 4.15.

| Option | Type | Default | Environment variable | Applies | Meaning |
|---|---|---|---|---|---|
| `LogsDir` | string | `logs` | `AMBROSE_LOGS_DIR` | Live | Folder for log files, relative to the working directory unless absolute; created when a File appender exists |
| `BindIP` | string | `0.0.0.0` | `AMBROSE_BIND_IP` | Rebinds live like the port option | Local address the listener binds; 0.0.0.0 listens on every IPv4 address |
| `WorldServerPort` | uint16 | `12333` | `AMBROSE_WORLD_SERVER_PORT` | Rebinds live; the new listener opens before the old one closes, and a failed bind keeps the old one | TCP port the realm listens on for game clients |
| `RealmID` | uint32 | `1` | `AMBROSE_REALM_ID` | Next start | The realm this game server runs; DB log rows carry it unless the appender names its own |
| `Patch.Enabled` | bool | `0` | `AMBROSE_PATCH_ENABLED` | Live, from the next zone transfer once milestone 16.07 consumes it | 0 for development with the client launched with -P 0 (doc/PATCHING.md); 1 lets the realm send download-package messages |
| `ClientDir` | string | empty | `AMBROSE_CLIENT_DIR` | At startup, and live once 4.15's reload triggers call `LocaleStore::Load`; a reload that fails keeps the active locale text | Your own Wizard101 install, the folder that holds `Data` and `Bin`. The locale store reads the `Locale/<locale>/*.lang` files of its `Data/GameData/Root.wad`. A file that fails to parse is skipped with a warning, and a default locale that cannot load at all stops the server at startup. Empty character name tables are extracted from the install as `Setup.Mode` allows. When the value is empty or holds no install and neither the environment nor the command line sets it, `Setup.Mode` decides at startup: `auto` uses the install with the newest revision found on this machine, `ask` offers the installs found, and `off` uses the value as it is. A chosen install is saved to `conf.d/client-data.conf` only when a type dump is in use for it, so a login server reading the same `conf.d` never starts from an install without one; otherwise the game server uses it for this run only and setup tries again on the next start. `auto` never replaces a value that names a folder without an install, which may be only unavailable for now: it uses the newest install for that run only and warns. An install found at a path that is not valid Unicode is skipped with a warning. With no install in use, locale keys stay unresolved |
| `Locale.Default` | string | `en-US` | `AMBROSE_LOCALE_DEFAULT` | At startup, and live once 4.15's reload triggers call `LocaleStore::SetDefaultLocale`, which applies only when the new locale loads | The locale folder keys resolve in when a caller names none, such as `en-US`, `de`, `es`, `fr`, `it`, `pl`, `el` or `gr`; it is parsed at startup and other locales load when first used. It is also the locale wizard names are checked and shown in when a caller names none; the server warns at startup when the world database's name tables have no human names for it, as for `gr` |
| `TypeDumpPath` | string | empty | `AMBROSE_TYPE_DUMP_PATH` | At startup, and live once 4.15's reload triggers reload it; a dump that fails to load keeps the active one | A type dump (format v2) made from your own client. Every class and property hash is checked when it loads, and one that fails to load at startup stops the server. Empty means the dump built from the install in use, `types/<revision>.json` in the Ambrose data folder (`%LOCALAPPDATA%/ProjectAmbrose` on Windows, otherwise `$XDG_DATA_HOME/project-ambrose` or `~/.local/share/project-ambrose`). In `auto` mode that dump is used when the revision and client program SHA-256 recorded in its header match the install, and otherwise `Setup.TypeExtractor` builds it first; it is never saved here. `ask` uses that dump without asking when it is current; otherwise it offers to build it when no dump found on this machine is named `<revision>.json` for the install, then offers the dumps found and saves the one chosen to `conf.d/client-data.conf`. `off` uses no dump. A value that is not a type dump is handled like an empty one, unless the environment or the command line sets it or `Setup.Mode` is `off`, and a value the command line sets empty stays empty, with no dump built or asked for. A dump found at a path that is not valid Unicode is skipped with a warning. With no dump in use, ObjectProperty data stays unreadable |
| `Setup.Mode` | string | `auto` | `AMBROSE_SETUP_MODE` | At startup | How the game server sets up its client data when `ClientDir` or `TypeDumpPath` is empty or unusable and not set by the environment or command line. `auto` never asks: in place of `ClientDir` it uses the install with the newest revision found on this machine, saving it to `conf.d/client-data.conf`, which then reloads, when `ClientDir` is empty, in place of `TypeDumpPath` it uses or builds the type dump of the install in use, and it extracts empty character name tables from that install. `ask` uses a current built type dump without asking, asks on an interactive terminal which install and type dump to use, or whether to build the dump, saves the choice to the same file, and asks before extracting empty name tables; without a terminal it logs what it found and the setting to add. In both modes an install is saved only when a type dump is in use for it. `off` searches for nothing, builds nothing and extracts nothing. Any other value is reported and runs as `auto` |
| `Setup.PromptTimeout` | uint32 | `120` | `AMBROSE_SETUP_PROMPT_TIMEOUT` | At startup | Seconds each setup question in `ask` mode waits for an answer; 0 waits forever. When time runs out or a stop signal arrives, that question and every later one are skipped |
| `Setup.TypeExtractor` | string | empty | `AMBROSE_SETUP_TYPE_EXTRACTOR` | At startup | The typeextract executable that builds the type dump of the install in use; empty uses `typeextract` beside the game server's executable. A relative path is resolved against the working directory and run as that exact file, never searched for on `PATH` |
| `Setup.TypeExtractTimeout` | uint32 | `900` | `AMBROSE_SETUP_TYPE_EXTRACT_TIMEOUT` | At startup | Seconds a type dump build may run before typeextract and everything it started are ended and the build fails; 0 sets no limit. Another process waits on a running build, however long it runs, and builds at once when the process holding the build lock has ended. A stop signal ends a build or the wait for one |
| `ObjectProperty.MaxDepth` | uint32 | `64` | `AMBROSE_OBJECT_PROPERTY_MAX_DEPTH` | Live, from the next decode once 4.15's reload triggers reload configuration; out-of-range values are clamped and reported | How deeply objects inside a decoded ObjectProperty blob may nest, from 1 to 128; the ceiling keeps a decode within a thread's stack |
| `ObjectProperty.MaxObjects` | uint32 | `65536` | `AMBROSE_OBJECT_PROPERTY_MAX_OBJECTS` | Live, from the next decode once 4.15's reload triggers reload configuration; out-of-range values are clamped and reported | How many objects one decoded blob may hold, from 1 to 16777216 |
| `ObjectProperty.MaxContainerCount` | uint32 | `65536` | `AMBROSE_OBJECT_PROPERTY_MAX_CONTAINER_COUNT` | Live, from the next decode once 4.15's reload triggers reload configuration; out-of-range values are clamped and reported | How many elements one list in a decoded blob may hold, from 0 to 16777216 |
| `ObjectProperty.MaxDecodedBytes` | uint64 | `16777216` | `AMBROSE_OBJECT_PROPERTY_MAX_DECODED_BYTES` | Live, from the next decode once 4.15's reload triggers reload configuration; out-of-range values are clamped and reported | Memory one decode may build, in bytes, from 65536 to 1073741824; objects, list elements, default values and strings are charged before they are allocated |
| `ObjectProperty.MaxInflatedSize` | uint64 | `4194304` | `AMBROSE_OBJECT_PROPERTY_MAX_INFLATED_SIZE` | Live, from the next decode once 4.15's reload triggers reload configuration; out-of-range values are clamped and reported | Largest size, in bytes, an enveloped blob may declare or inflate to, from 1024 to 268435456 |
| `LoginDatabaseInfo` | string | `127.0.0.1;3306;ambrose;ambrose;ambrose_login` | `AMBROSE_LOGIN_DATABASE_INFO` | Live like the login server's `LoginDatabaseInfo` | Login database, for accounts and realm state, in the connection string form described in doc/config/loginserver.md |
| `LoginDatabase.WorkerThreads` | uint32 | `1` | `AMBROSE_LOGIN_DATABASE_WORKER_THREADS` | Like `LoginDatabaseInfo` | Async connections, each with its own worker thread (0-64) |
| `LoginDatabase.SynchThreads` | uint32 | `1` | `AMBROSE_LOGIN_DATABASE_SYNCH_THREADS` | Like `LoginDatabaseInfo` | Connections for blocking queries (1-64) |
| `CharacterDatabaseInfo` | string | `127.0.0.1;3306;ambrose;ambrose;ambrose_characters` | `AMBROSE_CHARACTER_DATABASE_INFO` | Live like the login server's `LoginDatabaseInfo` | Characters database, in the connection string form described in doc/config/loginserver.md |
| `CharacterDatabase.WorkerThreads` | uint32 | `1` | `AMBROSE_CHARACTER_DATABASE_WORKER_THREADS` | Like `CharacterDatabaseInfo` | Async connections, each with its own worker thread (0-64) |
| `CharacterDatabase.SynchThreads` | uint32 | `1` | `AMBROSE_CHARACTER_DATABASE_SYNCH_THREADS` | Like `CharacterDatabaseInfo` | Connections for blocking queries (1-64) |
| `WorldDatabaseInfo` | string | `127.0.0.1;3306;ambrose;ambrose;ambrose_world` | `AMBROSE_WORLD_DATABASE_INFO` | Live like the login server's `LoginDatabaseInfo` | World database of templates, spawns and quests, in the connection string form described in doc/config/loginserver.md |
| `WorldDatabase.WorkerThreads` | uint32 | `1` | `AMBROSE_WORLD_DATABASE_WORKER_THREADS` | Like `WorldDatabaseInfo` | Async connections, each with its own worker thread (0-64) |
| `WorldDatabase.SynchThreads` | uint32 | `1` | `AMBROSE_WORLD_DATABASE_SYNCH_THREADS` | Like `WorldDatabaseInfo` | Connections for blocking queries (1-64) |
| `MaxPingTime` | uint32 | `30` | `AMBROSE_MAX_PING_TIME` | Like `LoginDatabaseInfo` | Minutes an idle database connection waits before it pings the server to stay open |
| `Updates.EnableDatabases` | uint32 | `7` | `AMBROSE_UPDATES_ENABLE_DATABASES` | At startup; schema updates never run on a live reload, so the running binary keeps the schema it was built for | Bitmask of databases the updater brings current before their pools open: 1 login, 2 characters, 4 world; a missing key means 0, none |
| `Updates.AutoSetup` | bool | `1` | `AMBROSE_UPDATES_AUTO_SETUP` | At startup | Create a missing database with utf8mb4. An empty database always gets `data/sql/base/db_<name>` imported, and a failed import into a database created this way drops it again |
| `Updates.SourcePath` | string | empty | `AMBROSE_UPDATES_SOURCE_PATH` | At startup | The Project Ambrose folder that holds `data/sql`; empty uses the folder the server was built from, then `share/ambrose` next to an installed `bin` |
| `Network.Threads` | uint32 | `1` | `AMBROSE_NETWORK_THREADS` | Live; new threads start at once, and removed threads stop taking sockets and exit when their last connection closes | Network threads that read and write sockets (1-256) |
| `Network.MaxFrameSize` | uint64 | `4194304` | `AMBROSE_NETWORK_MAX_FRAME_SIZE` | Next connection | Largest frame in bytes a client may send, checked before the frame is buffered (17 to 1 GiB) |
| `Network.MaxDmlMessages` | uint32 | `1024` | `AMBROSE_NETWORK_MAX_DML_MESSAGES` | Next connection | Most DML messages one frame may chain (at least 1) |
| `Network.MaxSendQueueBytes` | uint64 | `16777216` | `AMBROSE_NETWORK_MAX_SEND_QUEUE_BYTES` | Next connection | Most bytes a connection may have waiting to be sent (1 MiB to 1 GiB). A frame that would pass the limit is not queued and the connection is closed, so a client that stops reading cannot grow server memory without bound |
| `Network.LongFrameLength` | string | `BodyOnly` | `AMBROSE_NETWORK_LONG_FRAME_LENGTH` | Next connection | What a long frame's 32-bit length counts: `BodyOnly` or `HeaderAndBody`, until doc/CAPTURE.md settles it |
| `Network.OutKBuff` | int32 | `-1` | `AMBROSE_NETWORK_OUT_K_BUFF` | Next connection | Socket send buffer in bytes; -1 keeps the operating system default |
| `Network.TcpNoDelay` | bool | `1` | `AMBROSE_NETWORK_TCP_NO_DELAY` | Next connection | Disable Nagle's algorithm so small frames go out at once |
| `World.UpdateInterval` | uint32 | `50` | `AMBROSE_WORLD_UPDATE_INTERVAL` | Next tick | Milliseconds between world updates (1-10000) |
| `Log.Async.Enable` | bool | `0` | `AMBROSE_LOG_ASYNC_ENABLE` | Live | Write log lines on a dedicated thread; shutdown and exit drain every queued line |
| `Log.Async.QueueSize` | uint32 | `65536` | `AMBROSE_LOG_ASYNC_QUEUE_SIZE` | Live | Queued lines before the full-queue policy applies (1024-16777216) |
| `Log.Async.QueueFull` | uint8 | `0` | `AMBROSE_LOG_ASYNC_QUEUE_FULL` | Live | 0 waits for room, 1 drops the line and logs the drop count |
| `Log.Utc` | bool | `0` | `AMBROSE_LOG_UTC` | Live | Timestamps and file names in UTC instead of local time |
| `Log.PendingBuffer` | uint32 | `1000` | `AMBROSE_LOG_PENDING_BUFFER` | Live | Lines kept for an appender whose type registers later, such as DB |
| `Console.Colors` | uint8 | `1` | `AMBROSE_CONSOLE_COLORS` | Live, from the next line written | 0 never, 1 when stdout is a terminal, 2 always; `NO_COLOR` disables 1 |
| `Console.Enable` | bool | `1` | `AMBROSE_CONSOLE_ENABLE` | At startup, and live once 4.15's reload triggers restart the console reader | Read commands such as `help`, `status` and `shutdown` from standard input; 0 starts no input thread. On a terminal the app draws an `Ambrose> ` prompt with line editing, history and tab completion of command names; a redirected input is read line by line instead. A closed or redirected-from-nothing input leaves the server running, and a terminal owned by another foreground job is not read |
| `Appender.Console` | appender | `1,3,3,"1 9 3 13 7 7"` | `AMBROSE_APPENDER_CONSOLE` | Live | Colored console output at Info with time and level |
| `Appender.Server` | appender | `2,2,7,Server.log,w` | `AMBROSE_APPENDER_SERVER` | Live | Server.log in LogsDir, rewritten each start, with time, level and category |
| `Appender.Errors` | appender | `2,4,7,Errors.log,a,16M,10` | `AMBROSE_APPENDER_ERRORS` | Live | Warnings and worse, appended across restarts, rotated at 16 MiB keeping 10 backups |
| `Appender.Stream` | appender | `3,2,0,1000` | `AMBROSE_APPENDER_STREAM` | Live | Live records for the admin API with a 1000-record backlog |
| `Logger.root` | logger | `3,Console Server Errors Stream` | `AMBROSE_LOGGER_ROOT` | Live | Required fallback for every category |
| `Logger.server` | logger | `3,Console Server Errors Stream` | `AMBROSE_LOGGER_SERVER` | Live | App lifecycle, config and logging messages |
| `Logger.sql` | logger | `4,Console Server Errors Stream` | `AMBROSE_LOGGER_SQL` | Live | Database messages, warnings and worse |
| `Logger.sql.driver` | logger | `3,Console Server Errors Stream` | `AMBROSE_LOGGER_SQL_DRIVER` | Live | Database pools opening, closing, reconnecting and reconfiguring at Info |
| `Logger.sql.updates` | logger | `3,Console Server Errors Stream` | `AMBROSE_LOGGER_SQL_UPDATES` | Live | Database creation, base imports and applied update files at Info |
| `Logger.network` | logger | `3,Console Server Errors Stream` | `AMBROSE_LOGGER_NETWORK` | Live | Sockets and message traffic |
