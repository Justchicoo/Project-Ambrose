# supervisor options

See doc/config/README.md for the file format, layers, environment variable names, and reload triggers, and doc/config/logging.md for the full logging grammar. The supervisor also reads every option the admin API takes, which doc/config/loginserver.md documents, with `Admin.Enable` on by default because serving the panel and answering power requests is what it is for. It reads the same options a second time under the `Panel.` prefix for the panel's own listener, which is the front door people open in a browser: `Panel.Enable`, `Panel.BindIP`, `Panel.Port`, `Panel.Token`, `Panel.TokenFile`, `Panel.AllowPlainHttpRemote`, `Panel.CertificateFile`, `Panel.PrivateKeyFile`, `Panel.AuthFailureBurst`, `Panel.AuthFailuresPerSecond`, `Panel.MaxRequestBytes`, `Panel.Threads`, `Panel.DashboardDir`, `Panel.AllowedHosts`, `Panel.SessionIdleMinutes` and `Panel.SessionLifetimeHours` each mean for the panel what their `Admin.` twin means for an app, and every message about them names the `Panel.` option. `Panel.Enable` is `0` by default and `Panel.Port` is `12080`, which is clear of the login server's own `LoginServerPort` of 12000, since both run on one machine in the ordinary case. The panel listener binds this machine unless `Panel.CertificateFile` and `Panel.PrivateKeyFile` name a certificate and key, or `Panel.AllowPlainHttpRemote = 1` accepts that the token, sign-in passwords, two-factor codes and session cookies then cross the network unencrypted. `supervisor --panel-self-signed` writes a certificate that signs itself to those two paths and prints its fingerprint, for a panel on this machine. The panel's operators are its own, kept in its store and separate from any game account: on its first start with no operator it prints a one-time link, good for thirty minutes and only from the machine it runs on, that makes the owner with a name and password of their choosing, so no default password ever exists. `panel user list`, `panel user create <name>`, `panel user reset-password <name>`, `panel user disable <name>` and `panel user enable <name>` run on its console; create and reset-password take no password, printing a one-time link the operator sets their own from, so a password never reaches a console line, a log or an audit row. `Panel.TrustedProxies` is a comma-separated list of addresses and CIDR ranges the panel believes a forwarded header from; with it empty, and for a peer not on it, the peer's own address is the client's and `X-Forwarded-For` is ignored, so nobody can name an address a throttle, an audit row or a sign-in record would believe. `Panel.RateLimitBurst` (default 120) and `Panel.RateLimitPerSecond` (default 2) size the cost-weighted limit held against the signed-in caller and against the address: each route says what answering it costs, a route that says nothing is never held back, and a request over the limit is answered 429 with `Retry-After` and recorded once per caller and minute in the audit tables.

The Applies column says when a changed value takes effect after a configuration reload or a live edit. The supervisor reads the options below when it starts watching, so the panel's config page marks them restart-required with that reason; milestone 17.28 moves launch settings into the panel's own store, where they apply at an app's next start instead.

| Option | Type | Default | Environment variable | Applies | Meaning |
|---|---|---|---|---|---|
| `Panel.StoreFile` | string | empty | `AMBROSE_PANEL_STORE_FILE` | At startup | The SQLite file the panel keeps its sessions, audit rows and later its users in, so it works before any game database is configured. Empty uses `panel/panel.sqlite3` in the Ambrose data folder, beside the supervisor's saved state, and a relative path is resolved against the working directory. It is opened when the supervisor starts watching and brought up to date by the dated files in `data/sql/panel` |
| `Supervisor.Apps` | string | `loginserver gameserver patchserver` | `AMBROSE_SUPERVISOR_APPS` | At startup | The apps the supervisor runs, in start order, separated by spaces or commas. Each name is 1 to 32 letters, digits, dashes or underscores, names its own `App.<name>.*` options, and is the name the panel and the routes use. A name that does not fit or is given twice is reported and left out |
| `Supervisor.StateFile` | string | empty | `AMBROSE_SUPERVISOR_STATE_FILE` | At startup | Where the supervisor keeps each app's desired state and the identity of the process it started, so a restarted supervisor takes running apps back. Empty uses `supervisor/state.json` in the Ambrose data folder (`%LOCALAPPDATA%/ProjectAmbrose` on Windows, otherwise `$XDG_DATA_HOME/project-ambrose` or `~/.local/share/project-ambrose`), and a relative path is resolved against the working directory. The file is written through a temporary file and is readable only by this user |
| `Supervisor.OutputDir` | string | empty | `AMBROSE_SUPERVISOR_OUTPUT_DIR` | At startup | Folder holding each app's captured standard output and error, as `<app>/current.out`, `current.err`, `previous.out` and `previous.err`. Empty uses `supervisor/output` in the Ambrose data folder; a relative path is resolved against the working directory. This capture is the fallback log source: it holds what an app writes before its admin API is up, after it exits, and while its admin API is off |
| `Supervisor.OutputMaxBytes` | uint64 | `16777216` | `AMBROSE_SUPERVISOR_OUTPUT_MAX_BYTES` | At startup | How large one captured file may grow, from 65536 to 1073741824 bytes. Past it the supervisor empties the file and says so in the output, because the app keeps appending at the new end; the last 1000 lines of the run stay in memory either way, and the app's own log files keep the full history |
| `App.<name>.Program` | string | the app's name | `AMBROSE_APP_<NAME>_PROGRAM` | At startup | The executable to run. A name with no folder is taken from the folder holding the supervisor, and on Windows `.exe` is added when no extension is given; a relative path with a folder is resolved against the working directory. The file name without its extension is the name the app answers to, which is how its admin API token file and its ready line are found, so a second realm can run `gameserver` under another `<name>` |
| `App.<name>.Config` | string | `<name>.conf` | `AMBROSE_APP_<NAME>_CONFIG` | At startup | The config file the app is started with, resolved against the app's working folder. The supervisor also reads it to learn the app's admin API address, port and token, exactly as the app itself does |
| `App.<name>.WorkingDirectory` | string | empty | `AMBROSE_APP_<NAME>_WORKING_DIRECTORY` | At startup | The folder the app runs in; empty uses the supervisor's own working directory, and a relative path is resolved against it |
| `App.<name>.Autostart` | bool | `1` | `AMBROSE_APP_<NAME>_AUTOSTART` | At startup | Whether the app starts with the supervisor the first time it is watched. After that the saved state decides: an app stopped from the panel stays stopped, and an app started from the panel starts again with the supervisor |
| `App.<name>.StartTimeout` | uint32 | `120` | `AMBROSE_APP_<NAME>_START_TIMEOUT` | At startup | Seconds a start may take before the supervisor ends the app's process tree and records a failed start, from 1 to 3600. An app is ready when its admin API reports it running or, with the admin API off, when it prints its ready line. An app taken back from an earlier supervisor is never ended this way |
| `App.<name>.StopTimeout` | uint32 | `60` | `AMBROSE_APP_<NAME>_STOP_TIMEOUT` | At startup | Seconds a stop may take, counted after any countdown, from 1 to 3600. Halfway through, the supervisor interrupts the app's process group; at the end it ends the whole tree. Keep it above the app's own shutdown grace, such as `Login.ShutdownGrace` |
| `Admin.Enable` | bool | `1` | `AMBROSE_ADMIN_ENABLE` | Like the loginserver's | On by default here, unlike every other app: serving the panel and answering power requests is what the supervisor is for, so it has nothing to do with its admin API off |
| `Admin.Port` | uint16 | `12020` | `AMBROSE_ADMIN_PORT` | Like the loginserver's | TCP port the supervisor's admin API listens on; 0 takes a free port the operating system picks |
| `Admin.Threads` | uint32 | `8` | `AMBROSE_ADMIN_THREADS` | Like the loginserver's | Threads the admin API serves requests on (2-64). Higher here than in an app, because every panel request an operator makes and every relay to an app's own admin API is answered on these |
| `Appender.Server` | appender | `2,2,7,Supervisor.log,w` | `AMBROSE_APPENDER_SERVER` | Live | Supervisor.log in LogsDir, rewritten each start, with time, level and category |
| `Appender.Errors` | appender | `2,4,7,SupervisorErrors.log,a,16M,10` | `AMBROSE_APPENDER_ERRORS` | Live | Warnings and worse, appended across restarts, rotated at 16 MiB keeping 10 backups |
| `Panel.Enable` | bool | `0` | `AMBROSE_PANEL_ENABLE` | At startup, and live on a reload: 1 opens the panel listener and 0 closes it without a restart | Serve the panel on a listener of its own, separate from the supervisor's admin API. Off by default, so the panel is reached through the admin API until an operator turns its own door on |
| `Panel.BindIP` | string | `127.0.0.1` | `AMBROSE_PANEL_BIND_IP` | At startup, and live on a reload, which rebinds the listener | Address the panel listens on. Anything but loopback needs `Panel.CertificateFile` and `Panel.PrivateKeyFile`, or `Panel.AllowPlainHttpRemote = 1`; an unsafe bind stops startup with an error naming the option, and a reload that would leave one is refused while the old listener keeps serving |
| `Panel.Port` | uint16 | `12080` | `AMBROSE_PANEL_PORT` | Like `Panel.BindIP` | TCP port the panel listens on; 0 takes a free port the operating system picks |
| `Panel.Token` | string | empty | `AMBROSE_PANEL_TOKEN` | At startup, and live on a reload, which ends every browser session opened with the old one | Bearer token the panel takes, and the one the page trades for a session cookie. Empty generates one in a file of its own, readable only by this user. 17.46 signs panel users in instead |
| `Panel.TokenFile` | string | empty | `AMBROSE_PANEL_TOKEN_FILE` | Like `Panel.Token` | Where the panel's generated token is kept. Empty uses `panel.token` in the Ambrose data folder, or beside the config file on a machine with none |
| `Panel.AllowPlainHttpRemote` | bool | `0` | `AMBROSE_PANEL_ALLOW_PLAIN_HTTP_REMOTE` | Like `Panel.BindIP` | Serve the panel beyond this machine with no TLS. Off by default. With it on, the listener starts and logs a warning naming the option and saying that the token, sign-in passwords, two-factor codes and session cookies then cross the network unencrypted |
| `Panel.CertificateFile` | string | empty | `AMBROSE_PANEL_CERTIFICATE_FILE` | Like `Panel.BindIP`, and a changed file is picked up by a reload with no rebinding | Certificate chain in PEM the panel serves over TLS, leaf first. Read when the listener opens and on every reload, and refused by name when the key does not belong to the leaf, the chain is out of order or the dates do not hold today. A reload swaps the pair for the next handshake without dropping open connections, and keeps the old pair serving when the new one will not load. `supervisor --panel-self-signed` writes one for a panel on this machine and prints its fingerprint |
| `Panel.PrivateKeyFile` | string | empty | `AMBROSE_PANEL_PRIVATE_KEY_FILE` | Like `Panel.CertificateFile` | Private key of `Panel.CertificateFile`; either one set without the other stops startup |
| `Panel.AuthFailureBurst` | uint32 | `10` | `AMBROSE_PANEL_AUTH_FAILURE_BURST` | Live | Wrong tokens one address may send before the panel answers 429, from 1 to 100000 |
| `Panel.AuthFailuresPerSecond` | double | `1` | `AMBROSE_PANEL_AUTH_FAILURES_PER_SECOND` | Live | How fast that budget refills, from 0 to 100000; 0 never refills until the listener restarts |
| `Panel.MaxRequestBytes` | uint32 | `262144` | `AMBROSE_PANEL_MAX_REQUEST_BYTES` | Like `Panel.BindIP` | Largest request body the panel takes, from 1024 to 16777216 bytes; a larger one is answered 413 |
| `Panel.Threads` | uint32 | `8` | `AMBROSE_PANEL_THREADS` | Like `Panel.BindIP` | Threads the panel serves requests on (2-64) |
| `Panel.DashboardDir` | string | empty | `AMBROSE_PANEL_DASHBOARD_DIR` | Live | Folder holding the built panel the listener serves at `/`. Empty uses `dashboard` beside the supervisor executable |
| `Panel.AllowedHosts` | string | empty | `AMBROSE_PANEL_ALLOWED_HOSTS` | Live | Comma-separated host names the panel answers for besides IP addresses and `localhost`. A Host header that is none of them is refused with 400, so a page elsewhere cannot reach the panel by rebinding a name onto it |
| `Panel.SessionIdleMinutes` | uint32 | `720` | `AMBROSE_PANEL_SESSION_IDLE_MINUTES` | Live | Minutes a browser session may go unused before it ends, from 5 to 10080 |
| `Panel.SessionLifetimeHours` | uint32 | `168` | `AMBROSE_PANEL_SESSION_LIFETIME_HOURS` | Live | Hours a browser session lasts however much it is used, from 1 to 720 |
| `Panel.TrustedProxies` | string | empty | `AMBROSE_PANEL_TRUSTED_PROXIES` | Like `Panel.BindIP` | Comma-separated addresses and CIDR ranges whose `X-Forwarded-For` the panel believes. Empty, and for any peer not on the list, the peer's own address is the client's and the header is ignored. With entries, a forwarded list from a trusted peer is read from the right, past the trusted hops, to the first address that is not one, and that address is what every throttle, audit row and sign-in record uses. An entry that is not an address or a range is reported and left out |
| `Panel.RateLimitBurst` | uint32 | `120` | `AMBROSE_PANEL_RATE_LIMIT_BURST` | Like `Panel.BindIP` | How much a caller may spend before the panel holds them back, from 1 to 1000000. Each route says as it registers what answering it costs; a route that says nothing is uncosted and is never held back. The budget is counted against the signed-in caller and against the address, so one costly caller cannot crowd out a status read |
| `Panel.RateLimitPerSecond` | double | `2` | `AMBROSE_PANEL_RATE_LIMIT_PER_SECOND` | Like `Panel.BindIP` | How fast that budget refills, from 0 to 100000. A request over it is answered 429 with `Retry-After`, and one audit row records each held-back caller and minute |

## How a stop is asked for

A stop, a restart or the console's `stop` command tries, in order: the app's admin API (`POST /api/shutdown` with the countdown), a `shutdown` line on the app's input, which only an app this supervisor started still has, and an interrupt to the app's process group, which is Ctrl+Break on Windows and SIGTERM elsewhere. `kill` skips all of that and ends the process tree at once. The output says which way was taken and why.

## Console commands

`apps` lists every app with its state, process id and crash count. `start <app>`, `stop <app> [seconds]`, `restart <app> [seconds]` and `kill <app>` do what the panel's power buttons do. `shutdown` stops the supervisor itself and leaves the apps running; the next supervisor takes them back.
