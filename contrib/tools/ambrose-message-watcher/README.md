# Ambrose Message Watcher

This tool reads a log file generated by a running Ambrose server and reports every refused or unhandled client message it sees.

## What it is for

Use it while the server is being exercised by a scenario or a client session. It makes it easier to see which messages were refused or are not handled yet.

## How to run

```powershell
cd contrib\tools\ambrose-message-watcher
cmake -S . -B build
cmake --build build --config Debug --target ambrose-message-watcher
.\build\Debug\ambrose-message-watcher.exe logs\Server.log
```

Use `--follow` to keep the process open and print each matching message as it is appended:

```powershell
.\build\Debug\ambrose-message-watcher.exe logs\Server.log --follow
```

Stop follow mode with `Ctrl+C`.

## What it was run against

The focused validation used a synthetic log containing the current Ambrose message log forms. Run it against a local Ambrose server log before using its output as an investigation lead.

## What it prints

Example:

```text
MSG_LOGIN
MSG_CHARLIST
1:2
```

Without `--follow`, the tool prints a summary grouped by message name or service/order id:

```text
Refused or unhandled messages:
MSG_LOGIN : 2
MSG_CHARLIST : 1
1:2 : 1
```

The parser recognizes the current Ambrose log forms for unknown messages, messages not handled yet, messages never accepted by an app, and messages that only the server sends. It intentionally does not classify every dropped protocol violation as an unhandled message.

## What would disprove it

This tool is wrong if it counts a valid message as refused or unhandled, misses a matching log line, or reports a name that is not present in the matching line.
